## 什么是 RAG

**RAG（Retrieval-Augmented Generation，检索增强生成）** 是一种结合检索和生成的 AI 技术方案。

2020 年，Facebook AI Research（FAIR）团队在论文《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》中首次提出这一概念。2022 年 ChatGPT 发布后，大模型时代全面到来，RAG 随之被广泛应用和发展。

### 为什么需要 RAG

大语言模型（LLM）本身有两个根本局限：

1. **知识截止日期**：模型训练完成后，内部知识就固定了，无法了解训练后发生的新事物
2. **私有知识盲区**：模型只知道训练数据中的公开信息，不了解企业内部文档、个人笔记等私有数据

RAG 的解法是：**回答问题前，先从外部知识库里检索相关文档，把检索结果塞进上下文，再让模型基于这些资料回答。**

这样既不需要重新训练模型，又能让模型拿到最新、最私有的信息。

```
用户提问 → 检索相关文档 → 文档 + 问题 → 模型生成回答
```

## RAG 的三个发展阶段

RAG 技术已经历了三轮迭代，从简单到复杂逐步演进：

### 阶段一：原始 RAG（Naive RAG）

最基础的形态，流程只有三步：

1. **离线**：把文档切块，向量化后存入向量数据库（索引）
2. **在线检索**：用户提问时，把问题向量化，检索最相似的文档块
3. **生成**：将检索结果拼入 prompt，让模型回答

简单直接，但问题也明显：切块策略粗糙、检索质量有限、容易召回无关内容。

### 阶段二：高级 RAG（Advanced RAG）

在原始 RAG 的三个流程上精细化，重点优化检索质量：

- **预处理**：数据清洗、文档结构解析、去重
- **更好的切块策略**：滑动窗口、按语义边界切块（而非固定字符数）
- **查询优化**：对用户的 query 重写/扩展，提升召回率
- **混合检索**：同时用语义搜索（Embedding）和关键词搜索（BM25），用 RRF 融合排名
- **重排序（Re-ranking）**：用更精准的模型对初步召回结果二次排序

### 阶段三：模块化 RAG（Modular RAG）

高级 RAG 的工程化升级，将 RAG 流程拆解为可独立组合的模块（检索、过滤、路由、聚合、生成……），不同业务场景可以灵活选择和编排所需模块，类似搭积木。

## 核心概念：Embedding（向量化）

RAG 的语义检索依赖 **Embedding** 技术，理解它是理解 RAG 的关键。

### 传统搜索的局限

在传统数据库里搜索"小狗"，只能找到包含"小狗"字眼的文档——"柯基""金毛"这样的词会被完全漏掉，因为数据库不理解它们和"小狗"的语义关系。

传统做法需要人工打标签（特征工程），把"小狗"和"柯基""金毛"关联起来。但对于图像、音频、长文本这类非结构化数据，人工打标签的代价极高，特征数量会快速膨胀到无法维护。

### Embedding 的解法

Embedding 模型自动把文本（或图像、音频）转换成一个**高维数值向量**，向量中每一个维度捕捉数据的某种特征（词汇、语法、语义、情感、主题……）。

关键性质：**语义相近的内容，向量在高维空间里也相近**。

```
"小狗"   → [0.12, -0.34, 0.87, ...]  ┐
"金毛"   → [0.11, -0.31, 0.85, ...]  ┘ 向量很接近 → 语义相似
"量子力学" → [0.91,  0.44, -0.22, ...] → 向量差很远 → 语义无关
```

例如，用 OpenAI 的 `text-embedding-ada-002` 模型对"帮大家吃得更好，生活更好"这句话做 Embedding，会得到一个 **1536 维的浮点数数组**：

```
[0.01758577, 0.0077889464, ... -0.008381876, -0.004376229]
```

这 1536 个数字就是这句话语义的"坐标"，存入向量数据库后，就可以通过计算**余弦相似度**来找语义最接近的内容。

### 常用 Embedding 模型

| 数据类型 | 代表模型                                                     |
| -------- | ------------------------------------------------------------ |
| 文本     | `text-embedding-ada-002`（OpenAI）、`text-embedding-3-small` |
| 图像     | `clip-vit-base-patch32`                                      |
| 音频     | `wav2vec2-base-960h`                                         |

## RAG 完整工作流程

```
【离线构建阶段】
原始文档
  → 文档解析（PDF/Word/网页…）
  → 文本切块（按段落/滑动窗口）
  → Embedding 模型向量化
  → 存入向量数据库（索引）

【在线查询阶段】
用户提问
  → 查询向量化
  → 向量数据库检索 Top-K 相似块（语义搜索）
  → [可选] BM25 关键词搜索
  → [可选] RRF 融合两路结果
  → [可选] Re-ranking 精排
  → 拼接上下文 + 原始问题 → LLM 生成回答
```

---

## 总结

RAG 本质上是给大模型装了一个"实时查资料"的能力——模型不再靠记忆回答，而是先检索、再回答。随着技术迭代，从最简单的"检索+生成"发展到今天融合混合搜索、重排序、查询优化的成熟工程体系，已成为企业 AI 应用落地的核心基础设施。

# RRF 与 TF-IDF 详解

## 一、TF-IDF：关键词检索的基石

### 先从"直觉"出发

假设你在一堆文章里搜索关键词 **"苹果"**。

最朴素的方法：哪篇文章包含"苹果"就返回，但"苹果"出现10次的文章应该比出现1次的更相关——这就是 **TF（Term Frequency，词频）** 的直觉。

但只看词频有个致命问题：**"的""了""是"** 这种词在每篇文章都出现几十次，难道它们最相关？

所以需要给"稀有词"加权——这就是 **IDF（Inverse Document Frequency，逆文档频率）**。

### TF 和 IDF 的定义

```
TF(词t, 文档d)  = 词t在文档d中出现的次数

IDF(词t)        = log(总文档数 / 包含词t的文档数)
```

**IDF 的直觉：**

- "的"出现在 10000 篇文档里 → `log(10000/10000) = 0` → IDF 接近0，几乎不贡献分数
- "BM25"只出现在 5 篇文档里 → `log(10000/5) ≈ 7.6` → IDF 很高，说明这个词很有区分度

**TF-IDF 最终得分：**

```
score = TF(词t, 文档d) × IDF(词t)
```

对查询中的每个词都算一次，加起来就是这篇文档的总得分。

### TF-IDF 的两个缺陷

**缺陷1：长文档吃亏/占便宜**

一篇5000字的文章，"苹果"出现20次；一篇500字的文章，"苹果"出现5次。
哪篇更相关？按 TF 算是前者，但500字文章里每100字就出现1次"苹果"，明显更聚焦。
TF-IDF 对文档长度没有惩罚，长文档天然占便宜。

**缺陷2：词频无上限**

"苹果"出现1次和出现100次，得分差100倍——但实际上出现了10次之后，再多出现对"相关性"的贡献已经很小了。
TF-IDF 的词频贡献是线性的，不符合人类直觉。

## 二、BM25：TF-IDF 的工程升级版

BM25（Best Match 25）是搜索引擎工业界用了几十年的标准算法，是 Elasticsearch、Lucene 的默认排序算法。
"25"是指这是第25次实验得到的最佳参数组合。

### BM25 公式

```
BM25 = Σ  IDF(t) × [TF × (k1+1)] / [TF + k1×(1 - b + b × |d|/avgdl)]
```

看起来复杂，拆开来其实只改了两件事：

### 改进1：TF 饱和（解决"词频无上限"问题）

原来的 TF 是线性的，BM25 把它改成一个有上限的曲线：

```
饱和TF = TF × (k1+1) / (TF + k1)      ← 简化版，忽略长度惩罚
```

用数字感受一下（k1=1.5）：

| 词频 TF | 原始TF | BM25饱和TF   |
| ------- | ------ | ------------ |
| 1       | 1      | 1.00         |
| 3       | 3      | 1.80         |
| 10      | 10     | 2.31         |
| 100     | 100    | 2.49         |
| ∞       | ∞      | 2.50（上限） |

**关键洞察：** 词频从1增到100，BM25 得分只从1增到2.49——而原始TF是线性增长100倍。
`k1` 参数控制饱和速度：k1越大，饱和越慢（高词频加分更多）；k1越小，饱和越快。

### 改进2：文档长度惩罚（解决"长文档占便宜"问题）

```
长度惩罚项 = 1 - b + b × (文档长度 / 平均文档长度)
```

- 文档长度 = 平均长度时，惩罚项 = 1，不惩罚不奖励
- 文档长度 > 平均长度时，惩罚项 > 1，分母变大，得分下降
- 文档长度 < 平均长度时，惩罚项 < 1，分母变小，得分上升

`b=0.75` 表示 75% 程度地按长度惩罚；`b=0` 完全不惩罚（退化为简单TF饱和）；`b=1` 完全按比例惩罚。

### 完整直觉

> 同样提到了"苹果"3次，一篇100字的短文比一篇5000字的长文更相关——BM25 会给短文更高分。
> 同样是短文，"苹果"出现3次和30次的差距没有TF-IDF算出的那么悬殊——因为TF已饱和。

## 三、RRF：融合多路检索结果的"裁判"

RRF（Reciprocal Rank Fusion，倒数排名融合）
一句话：不看分数，只看排名，用排名的倒数来融合多路检索结果。

### 问题：两路检索结果怎么合并？

现代 RAG 系统通常同时跑两路检索：

- **语义检索**（Embedding）：把文本转成向量，计算余弦相似度，分数范围约 `[0, 1]`
- **关键词检索**（BM25）：统计词频，分数可能是 `0.3`、`2.7`、`15.4`……

现在要把两路结果合并，问题来了：

> 语义得分 `0.85` 和 BM25 得分 `3.2`，哪个更好？

这两个数字**完全不同量纲**，就像问"100元人民币和50美元哪个多"，无法直接比较。

### 方案一（有缺陷）：归一化后加权

把两路分数各自压缩到 `[0, 1]`（Min-Max 归一化），然后加权：

```
finalScore = 语义分_归一化 × 0.65 + 关键词分_归一化 × 0.35
```

**问题：** 归一化受极端值干扰。如果有一个文档的 BM25 得分异常高（比如 50.0），其他所有文档归一化后都会被压缩到接近 0，信息大量丢失。权重 0.65/0.35 也需要人工经验调参。

### 方案二（RRF）：只看排名，不看分数

RRF 的核心思路：**把两路检索结果都按各自的相关性排好名，然后只用排名位置来融合。**

```
RRF分数 = 1/(k + 语义排名) + 1/(k + 关键词排名)
```

其中 `k=60` 是平滑常数（防止第1名权重太极端）。

**具体例子：** 搜索"什么是 RAG"，有以下文档：

| 文档            | 语义检索排名 | BM25排名 | RRF 分（k=60）           |
| --------------- | ------------ | -------- | ------------------------ |
| RAG介绍.md      | 第1名        | 第2名    | 1/61 + 1/62 ≈ **0.0325** |
| 向量数据库.md   | 第2名        | 第1名    | 1/62 + 1/61 ≈ **0.0325** |
| 检索算法对比.md | 第3名        | 未出现   | 1/63 + 0 ≈ **0.0159**    |
| Python入门.md   | 未出现       | 第3名    | 0 + 1/63 ≈ **0.0159**    |

**读懂这张表：**

- RAG介绍.md 和 向量数据库.md 并列第一，因为两路都高度认可它们
- 检索算法对比.md 排第三，语义觉得相关但关键词没找到（可能文中没有"RAG"这个词但语义相近）
- Python入门.md 排第四，关键词找到了（可能文中提到了"RAG"）但语义不相关

### RRF 为什么好用

1. **无量纲问题**：只比排名，不比分数，语义和关键词天然可以融合
2. **不受极端值影响**：某路出现异常高分不影响另一路的贡献
3. **不需要调权重**：公式里没有 0.65/0.35 这样的人工参数
4. **两路互相验证**：只有两路都认为相关的文档才能得高分，减少误召回

### k=60 的直觉

如果 k=0，公式变成 `1/rank`，第1名得1分，第2名得0.5分，第3名得0.33分——差距太大，排名靠前的文档会完全碾压后面的。

k=60 把差距"压平"：

| 排名   | k=0 时得分 | k=60 时得分 |
| ------ | ---------- | ----------- |
| 第1名  | 1.000      | 0.0164      |
| 第2名  | 0.500      | 0.0161      |
| 第10名 | 0.100      | 0.0143      |
| 第50名 | 0.020      | 0.0091      |

k=60 时前10名分数很接近，这意味着"排名第2"不会被"排名第1"完全压制——如果第2名在另一路排名很靠前，RRF 仍会把它提到前面。

## 四、三者定位总结

```
你有一堆文档，用户输入了一个查询
         │
         ├─ 关键词路：BM25
         │    └─ 对每个文档算 BM25 分数（考虑了词频饱和+长度惩罚）
         │    └─ 按分数排名：文档A第1，文档C第2，文档B第3……
         │
         ├─ 语义路：Embedding + 余弦相似度
         │    └─ 对每个文档算语义相似度
         │    └─ 按分数排名：文档B第1，文档A第2，文档D第3……
         │
         └─ RRF 裁判：
              └─ 取两路排名，用 1/(k+rank) 公式各自贡献分数
              └─ 加总后重新排名 → 最终结果
```

|            | 解决什么问题           | 核心机制            | 适合什么场景       |
| ---------- | ---------------------- | ------------------- | ------------------ |
| **TF-IDF** | 关键词稀有度加权       | 词频 × 逆文档频率   | 简单关键词匹配基线 |
| **BM25**   | TF 饱和 + 文档长度惩罚 | 非线性TF + 长度归一 | 工程级关键词检索   |
| **RRF**    | 融合多路异质分数       | 排名倒数求和        | 混合检索最终排名   |

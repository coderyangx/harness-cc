# 混合搜索（Hybrid Search）

## 什么是混合搜索

混合搜索是将**语义搜索**和**关键词搜索**两种方式结合起来的检索策略，目标是取长补短，提升整体检索质量。

在标准 RAG 流程中，通常只使用语义搜索：把文本用编码器模型转换成高维向量（Embedding），查询时计算向量余弦相似度，返回最相近的文档片段。这种方式能理解语义，但会漏掉一些精确的关键词匹配场景。

混合搜索同时跑两路，再把结果合并。

---

## 两种搜索方式的对比

|                  | 语义搜索                                | 关键词搜索（BM25）                             |
| ---------------- | --------------------------------------- | ---------------------------------------------- |
| **原理**         | 文本 → 向量，计算余弦相似度             | 统计词频，计算 TF-IDF 得分                     |
| **擅长**         | 同义词、近义词、改写表达                | 专有名词、型号、精确匹配                       |
| **怕什么**       | 没见过的专有名词、缩写                  | 用词和文档不完全一致时失效                     |
| **典型失败场景** | 搜索"iPhone 16 Pro Max"可能返回其他手机 | 搜索"价格实惠的手机"找不到没有"价格"字眼的文档 |

**混合搜索的核心价值**：两路互为补充——语义路找"意思相近"的，关键词路找"字面匹配"的，两路都认可的结果更可信。

---

## 关键词搜索：BM25 算法

BM25（Best Match 25）是关键词搜索的工业标准，Elasticsearch 的默认排序算法就是它。

BM25 建立在 TF-IDF 思想之上：

- **TF（词频）**：这个词在文档里出现越多，越相关
- **IDF（逆文档频率）**：这个词越稀有，贡献越大——"的""了"几乎每篇都有，区分度为零；"BM25""RRF"只在少数文档出现，找到了就很有意义

相比 TF-IDF，BM25 做了两项关键改进：

1. **TF 饱和**：词频增长到一定程度后不再线性加分，避免"堆词"刷分
2. **文档长度惩罚**：长文档词多 TF 天然高，BM25 对此补偿，让长短文档公平竞争

## 融合两路结果：RRF 算法

两路检索结果合并时，最大的挑战是：语义得分（余弦相似度，约 `0~1`）和 BM25 得分（`0.5`、`12.3`……）**量纲完全不同**，无法直接相加。

**RRF（Reciprocal Rank Fusion，倒数排名融合）** 的解法是：不看原始分数，只看**排名位置**。

```
RRF 分 = 1/(k + 语义排名) + 1/(k + 关键词排名)
```

例如：

| 文档 | 语义排名 | BM25排名 | RRF 分（k=60）            |
| ---- | -------- | -------- | ------------------------- |
| A    | 第1名    | 第2名    | 1/61+1/62 ≈ 0.0325（第1） |
| B    | 第3名    | 第1名    | 1/63+1/61 ≈ 0.0322（第2） |
| C    | 第2名    | 未出现   | 1/62+0 ≈ 0.0161（第3）    |

文档 C 语义排第2，但关键词路完全没出现它，说明两路对它的认可度不一致，最终排到第3。
文档 A 和 B 两路都靠前，获得最高 RRF 分。

RRF 的优点：无量纲问题、不受极端分数干扰、不需要手动调权重。

## 完整流程

```
用户查询
   │
   ├── 语义检索路 ──── Embedding → 余弦相似度 → 按分数排名
   │
   ├── 关键词检索路 ── BM25 分词统计 → 按分数排名
   │
   └── RRF 融合 ──── 取两路排名 → 1/(k+rank) 求和 → 最终排序 → Top-K 结果
```

## 选择哪种搜索

哪种搜索方法更好？这要看情况。两者都有优点和缺点。

1. 使用 BM25 进行关键字搜索会查找查询词的精确匹配。 当寻找短语的精确匹配时，这非常有用，如果我正在寻找“戴帽子的猫”，我可能正在寻找这本书/电影。我不想要语义上类似于帽子或猫的相似结果。关键字搜索的另一个用例是**编程**。如果我正在寻找特定的函数或代码段，我想要完全匹配。
2. 另一方面，语义搜索寻找语义相似的内容。这意味着语义搜索还可以查找具有同义词或不同拼写的文档，例如复数、大写等。

由于这两种算法都有其用例，因此**混合搜索**会使用这两种算法，然后将它们的结果合并为一个最终排名。

混合搜索的缺点是：它比只运行一种算法需要更多的计算资源。

## 什么时候用混合搜索

- 查询中**同时包含**语义意图和精确关键词（如"2024年最新的 RAG 优化方法"）
- 数据集中有**大量专有名词、产品型号、人名、代码**
- 纯语义搜索或纯关键词搜索单独效果不佳时

纯语义搜索对于日常自然语言查询已经足够好；混合搜索主要在需要精确召回的专业场景下带来明显提升。
